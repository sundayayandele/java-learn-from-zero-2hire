## What this module gives you

Two weeks that make you faster and more employable. Week 23 is about **AI-assisted engineering**: using coding assistants such as GitHub Copilot, Claude Code and Cursor for real work, reviewing their output for bugs, security problems and licence risk, and using them for tests, documentation and refactoring without handing over your understanding. Week 24 turns everything you have built into a **junior portfolio**: a CV, GitHub profile and LinkedIn tuned for Java roles, and structured interview preparation covering core Java, Spring, SQL and live coding.

Employers increasingly expect engineers to use AI tools well. They also test, in interviews and on the job, whether you understand the code you ship. This module teaches both.

**Exit check for Module 9:** all five topic CBTs passed; projects 9.A and 9.C completed; 9.B booked.

## Module projects

### Project 9.A: Polished junior portfolio (4–5 projects) with READMEs

- Pick your best four or five repositories (at least three capstones). Each needs: a README a hiring manager can read in three minutes, an architecture diagram, a live health URL or demo video, green CI with quality gates, and a short "what I'd do next" section.
- A GitHub profile README that pins them and states the roles you are targeting.
- An **AI usage note** in each README: which parts you wrote with an assistant, and how you verified them.

### Project 9.B: Mock technical interview with feedback

- A 60-minute mock interview with a mentor or peer: 15 minutes of core Java and Spring questions, 25 minutes of live coding (no AI assistant), 15 minutes walking through one capstone's design, 5 minutes for your questions.
- Record written feedback against the interview rubric in topic 9.5, and a plan for your two weakest areas.

### Project 9.C: Tailored CV and application plan

- A one-page CV for junior Java backend roles with quantified project bullets (for example "reconciled 1M records per side in 3 minutes").
- A shortlist of 15 real roles (banks, fintechs, consultancies, remote) with a job-ad-to-evidence map for each, and a four-week application plan with weekly targets.

### Lab 9.D: Review an AI-generated pull request

A broken-service lab: [Review an AI-generated pull request](../../../labs/09-ai-pull-request-review/README.md), an AI-written fee service whose own tests pass while the product specification tests fail. Do it alongside the module; it counts as practice, not as the module project, but mentors review it if you submit it with your project.

## How these projects are assessed

| Criterion | Not yet | Competent | Strong |
| --- | --- | --- | --- |
| Portfolio quality | Repositories without READMEs or CI | Four or more projects with READMEs, diagrams, green CI and live links | Each README tells a clear story with numbers, trade-offs and next steps |
| Responsible AI use | AI output pasted without review | AI usage disclosed and verified with tests | Review notes show bugs or risks found in AI output and how they were fixed |
| CV and profiles | Generic CV, empty profiles | One-page CV, quantified bullets, consistent GitHub and LinkedIn | Tailored versions per role family, endorsements or recommendations |
| Interview readiness | Not practised | Mock interview done, feedback recorded | Improvement plan executed and a second mock shows progress |
| Application plan | None | Shortlist with evidence map | Weekly targets tracked, follow-ups and referrals planned |
