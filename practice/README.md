# Coding-interview practice track (weeks 3–25)

← [Home](../README.md) · [Phase 1](../phases/01-foundations/README.md) · [Phase 2](../phases/02-professional-backend/README.md)

Most junior Java hiring loops start with an **online assessment** (HackerRank, Codility or similar): two or three timed problems on arrays, strings, hash maps, sorting and basic data structures, often plus SQL. Projects get you interviews; this track gets you **through the first round**. It runs alongside both phases, about **3 hours a week**:

- **46 Java problems** in [`dsa/`](dsa/), auto-graded by JUnit tests, with fintech-flavoured statements.
- **24 SQL interview drills** in [`sql/`](sql/), auto-graded against a real PostgreSQL 17 with Testcontainers.
- **57 classic problems** on LeetCode (all free), mapped to the same patterns.

That's **127 problems** in total, ordered by pattern so each week builds on the last.

## How to work

1. Fork or copy this folder into your own repository (keep it public: it's portfolio evidence).
2. Each week, open that week's problems below. Read the statement in the Javadoc or SQL header, then **set a timer for 25 minutes** (easy) or 40 minutes (medium).
3. Say your approach out loud first: brute force, its complexity, then the better idea. This is exactly what interviewers listen for.
4. Implement it in `src/main/java` (Java) or under the `-- Your query below:` line (SQL), then run the tests:

```bash
cd practice/dsa && ./mvnw test -Dtest=TwoSumTransfersTest          # one Java problem
cd practice/dsa && ./mvnw test -Dpractice.ignoreFailures=true      # all of them, with a progress summary
cd practice/sql && ./mvnw test -Ddrill=07                          # one SQL drill (Docker must be running)
cd practice/sql && ./mvnw test                                      # all drills
```

5. Only after you pass (or after 45 stuck minutes), compare with the reference in `dsa/solutions/` or `sql/solutions/`, and write one line in a `NOTES.md`: the pattern, the complexity, and the mistake you made.
6. Redo any problem you needed the solution for one week later, without looking.

The Java stubs are generated from the solutions by `scripts/practice_stubs.py`, and CI proves every test passes against the reference solutions (`-Psolutions`), so a failing test always means your code, not the test.

## What interviewers check in these rounds

- You ask about input size, empty input, duplicates, negatives and ties **before** coding.
- You state time and space complexity (Big-O) and can improve a brute-force solution.
- You choose the right Java structure: `HashMap`/`HashSet` for lookups, `ArrayDeque` (not `Stack`) for stacks and queues, `PriorityQueue` for top-k, `TreeMap` for ordered keys, `StringBuilder` in loops, `Comparator.comparing(...).thenComparing(...)` for sorting.
- You handle money with `long` minor units or `BigDecimal`, never `double`.
- Your SQL uses joins, `GROUP BY`/`HAVING`, window functions (`ROW_NUMBER`, `RANK`, `DENSE_RANK`, `LAG`, running `SUM`), anti-joins and CTEs correctly, and handles `NULL` and ties.

## Checkpoints on ITLearning

Each course also has a **Coding practice quiz** on Moodle: 15 of these Java problems per phase, graded in the browser on our sandbox server, with unlimited checks. It's a quick way to practise without a local setup; the full track and its tests live here.

Each phase has a **Coding practice checkpoint** assignment on Moodle: submit your repository link and the test summary. Phase 1 (week 14) expects at least 70% of that phase's Java and SQL problems passing; Phase 2 (week 25) expects at least 70% of all of them. Phases 1 and 2 each also include a **timed live-coding assessment** built on the same patterns.
