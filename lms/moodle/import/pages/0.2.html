Week 0 · Module 0: Programming On-Ramp

What you will be able to do

  • Make decisions with if, else if and else, combining conditions with &&, || and !.
  • Repeat work with while and for loops, and stop them at the right moment.
  • Store a list of values in an array, loop over it, and find a total, a maximum and a count.
  • Work with text: length, characters, comparing strings and building output.
  • Trace a short program by hand in a table, which is how you find bugs before the computer does.

Why this matters in a bank or fintech

Most business rules are decisions and loops: "if the account is frozen, reject the transfer", "for every transaction today, add it to the total", "keep asking for the PIN until it's right or three attempts are used". Off-by-one loops and wrong conditions are among the most common real bugs in payment code. Tracing by hand is how you catch them in a code review.

1. Comparisons and decisions

A condition is an expression that is true or false:

Operator Meaning Example
== equal (numbers, boolean) attempts == 3
!= not equal status != 0
<, <=, >, >= less, at most, greater, at least amount <= balance
&& and: both must be true amount > 0 && amount <= balance
|| or: at least one is true isFrozen || isClosed
! not !isFrozen

if runs a block only when its condition is true:

long balance = 800_000;       // kobo
long amount = 950_000;
boolean isFrozen = false;

if (isFrozen) {
    System.out.println("Rejected: account frozen");
} else if (amount <= 0) {
    System.out.println("Rejected: amount must be positive");
} else if (amount > balance) {
    System.out.println("Rejected: insufficient funds");
} else {
    balance -= amount;
    System.out.println("Approved. New balance: " + balance);
}

Java checks the conditions top to bottom and runs only the first block that matches. Order matters: put the most specific rules first. Always use braces { }, even for one line; a missing brace is a famous source of bugs.

Comparing text: never use == for strings. Use .equals:

String channel = in.nextLine();
if (channel.equals("USSD")) { ... }           // correct
if (channel.equalsIgnoreCase("ussd")) { ... } // ignores capital letters

== on strings asks "are these the same object in memory?", which is sometimes true and sometimes false for equal text. Topic 1.3 explains why.

Try it: add a rule that transfers over ₦1,000,000 need approval, and decide where in the chain it belongs.

2. while loops: repeat until something changes

A while loop repeats its block as long as its condition is true:

Scanner in = new Scanner(System.in);
int attempts = 0;
boolean unlocked = false;

while (!unlocked && attempts < 3) {
    System.out.print("Enter PIN: ");
    String pin = in.nextLine();
    attempts++;                          // same as attempts = attempts + 1
    if (pin.equals("4321")) {
        unlocked = true;
    } else {
        System.out.println("Wrong PIN. " + (3 - attempts) + " attempt(s) left.");
    }
}
System.out.println(unlocked ? "Welcome" : "Card blocked");

Something inside the loop must eventually make the condition false (here, attempts++ or unlocked = true). If nothing does, you have an infinite loop: the program never stops. Press Ctrl+C to stop it, then find the variable that should have changed.

3. for loops: repeat a known number of times

When you know how many times to repeat, a for loop keeps the counter in one place:

long balance = 10_000_000;               // ₦100,000.00 in kobo
for (int month = 1; month <= 6; month++) {
    balance += 2_000_000;                // save ₦20,000 a month
    System.out.println("Month " + month + ": " + balance);
}

The three parts in the brackets are: start (int month = 1), keep going while (month <= 6), and after each round (month++). This loop runs for months 1, 2, 3, 4, 5 and 6: six times.

Off-by-one errors are the classic loop bug. month < 6 runs five times; month <= 6 runs six. When you write a loop, ask: "what is the first value, what is the last value, and how many rounds is that?"

4. Arrays: many values under one name

An array holds a fixed number of values of the same type, numbered from 0:

long[] transfers = {250_000, 1_200_000, 75_000, 980_000};   // kobo
System.out.println(transfers.length);   // 4
System.out.println(transfers[0]);       // 250000, the first
System.out.println(transfers[3]);       // 980000, the last: index length - 1

The last index is always length - 1. Reading transfers[4] stops the program with ArrayIndexOutOfBoundsException: Index 4 out of bounds for length 4.

Loop over every element to total, count or find the largest:

long total = 0;
long largest = transfers[0];
int over500k = 0;
for (int i = 0; i < transfers.length; i++) {
    total += transfers[i];
    if (transfers[i] > largest) {
        largest = transfers[i];
    }
    if (transfers[i] > 50_000_000) {       // over ₦500,000
        over500k++;
    }
}
System.out.println("Total " + total + ", largest " + largest + ", large transfers " + over500k);

These three patterns, accumulate (total), track the best so far (largest) and count matches, solve a surprising number of problems. Start largest with the first element, not 0, or a list of negative numbers gives the wrong answer.

When you don't need the index, the enhanced for loop reads better:

for (long t : transfers) {
    total += t;
}

To create an empty array of a given size: long[] daily = new long[7]; (seven zeros), then fill it with daily[i] = ....

5. Strings: working with text

String ref = "TRF-2026-00042";
ref.length()              // 14
ref.charAt(0)             // 'T' (a char: one character, in single quotes)
ref.startsWith("TRF")     // true
ref.substring(4, 8)       // "2026": from index 4 up to, but not including, 8
ref.indexOf("-")          // 3, the first position of "-"
ref.toLowerCase()         // "trf-2026-00042"
ref.contains("0042")      // true
"  ada  ".strip()         // "ada": spaces removed from both ends

Strings never change: toLowerCase() returns a new string and leaves ref as it was. Write ref = ref.toLowerCase(); if you want to keep the result.

Loop over the characters of a string like an array:

String accountNumber = "0123456789";
boolean allDigits = accountNumber.length() == 10;
for (int i = 0; i < accountNumber.length(); i++) {
    char c = accountNumber.charAt(i);
    if (c < '0' || c > '9') {
        allDigits = false;
    }
}
System.out.println(allDigits ? "Valid format" : "Invalid account number");

6. Tracing by hand

When a loop gives the wrong answer, don't change code at random. Trace it: write a table with one column per variable and one row per round of the loop, and fill it in as the computer would.

int[] scores = {45, 72, 50};
int passed = 0;
for (int i = 0; i < scores.length; i++) {
    if (scores[i] > 50) {
        passed++;
    }
}
i scores[i] scores[i] > 50? passed after
0 45 false 0
1 72 true 1
2 50 false 1

The trace shows the bug immediately: a score of exactly 50 should pass, so the condition must be >= 50. Tracing takes two minutes and finds bugs that staring at code doesn't. Professional engineers do the same thing with a debugger (topic 2.6).

Worked example: a mini statement

public class Main {
    public static void main(String[] args) {
        String[] descriptions = {"Salary", "Airtime", "Rent", "Transfer from Bola"};
        long[] amounts = {45_000_000, -150_000, -18_000_000, 2_500_000};   // kobo; negative = debit
        long balance = 1_000_000;

        System.out.println("Opening balance: " + balance);
        long credits = 0, debits = 0;
        for (int i = 0; i < amounts.length; i++) {
            balance += amounts[i];
            if (amounts[i] >= 0) {
                credits += amounts[i];
            } else {
                debits -= amounts[i];            // store debits as a positive total
            }
            System.out.println(descriptions[i] + ": " + amounts[i] + " -> " + balance);
        }
        System.out.println("Credits " + credits + ", debits " + debits + ", closing " + balance);
        System.out.println(balance == 1_000_000 + credits - debits ? "Reconciled" : "MISMATCH");
    }
}

The last line is a reconciliation check: the closing balance must equal the opening balance plus credits minus debits. Banks run exactly this check every night on every account.

Common mistakes

  • Comparing strings with == instead of .equals.
  • = (store) where you meant == (compare): Java usually refuses to compile if (attempts = 3), which is a gift.
  • Off-by-one bounds: i <= array.length reads one element too many.
  • A while loop whose condition never becomes false.
  • Starting a "largest so far" variable at 0 instead of the first element.
  • Forgetting that strings never change: calling name.strip(); without storing the result.

Practice

  1. Read an amount and a channel (USSD, APP or POS) and print the fee: USSD ₦6.98 flat, APP free under ₦5,000 and ₦10 above, POS 0.5% capped at ₦100.
  2. Print the 7 times table from 7 × 1 to 7 × 12 with a for loop. Then do it with a while loop.
  3. Given long[] dailySales, print the best day, the worst day, the average (whole kobo) and how many days beat the average.
  4. Mask an account number: "0123456789" becomes "******6789". Use length(), substring and a loop or "*".repeat(n).
  5. Trace this by hand before running it, then check: int n = 5, f = 1; while (n > 1) { f = f * n; n--; }. What is f?
