Getting hired after Phase 2 (week 25, then ongoing)

Phase 2 is the junior launch point. After week 25 you can compete for junior Java backend engineer roles at Nigerian fintechs and banks, for graduate and associate roles at consultancies, and for remote junior roles that ask for Java, Spring Boot, REST, security and CI/CD. Phase 1's advice still holds (read it if you skipped it); this page adds what changes now that you have integration, security, testing and delivery skills.

What you can honestly claim after Phase 2

You can say Evidence they'll check
"I design and integrate REST APIs, including payment providers and webhooks" Capstone 1: OpenAPI contract, signed webhooks, idempotency keys, a WireMock test suite
"I secure APIs with Spring Security, OAuth2 and JWTs, and I prevent broken object level authorisation" A Keycloak-secured capstone with 401/403/404 tests for every endpoint
"I write a real test pyramid: unit, integration with Testcontainers, API tests, coverage gates" A green pipeline with the coverage gate and the test report
"I ship through quality-gated CI/CD and Docker" Required checks on main, Trivy scans, an SBOM, a deployed service
"I use AI coding assistants productively and review their output critically" A PR where you rejected or corrected AI-generated code, with the reason; your project instruction file
"I work in pull requests with reviews" PR history with descriptions and review comments

Still don't claim Kafka, Kubernetes in production, microservices or cloud certifications: Phase 3 covers those.

Your junior portfolio (4–5 projects)

Pin four or five repositories and order them for the jobs you want:

  1. Capstone 1 (payment gateway hub): your headline project for payments and fintech roles.
  2. Your second Phase 2 capstone (and a third if you built one), chosen for your target employers: open banking or KYC for banks, tokenisation or merchant platform for payment companies, GraphQL or gRPC for product engineering teams.
  3. Phase 1 Capstone 1 (ledger) or your best Phase 1 capstone: it shows SQL and concurrency depth.
  4. Optional: an open-source contribution or the Module 9 portfolio project.

Each README leads with a one-line result, for example "Payment hub: provider failover in under a second, duplicate webhooks applied once, 94% line coverage, deployed with Keycloak." Add the architecture diagram, the threat model and a 3-minute demo video.

CV for a Phase 2 graduate

  • Title it for the role: Junior Java Backend Engineer.
  • Three project entries, each with stack, what you built, and one verifiable result (see topic 9.4 for strong bullet patterns).
  • Skills, grouped and honest: Java 21, Kotlin basics, SQL · Spring Boot 4, Spring Security 7, Spring Data, springdoc OpenAPI · PostgreSQL, Redis, MongoDB, Flyway · JUnit, Mockito, Testcontainers, WireMock, JaCoCo · Docker, GitHub Actions, GitLab CI, Jenkins, Azure DevOps · Keycloak, OAuth2/OIDC, OWASP Top 10.
  • Mention responsible AI-assisted development in one line, with evidence, not as a headline.
  • Keep it to one page; export to PDF; no skills in images (topic 9.4).

Interview loop: what's new at junior level

Round What it tests now How to prepare
Online assessment Core Java, SQL, one medium coding problem Weekly timed practice continues: 2 easy, 1 medium, 10 SQL
Technical: API design Resource design, status codes, idempotency, pagination, versioning, error format Design an API on a whiteboard for "refunds" or "standing orders" in 20 minutes, then compare with Capstone 1
Technical: security Filter chain, JWT validation, OAuth2 flows, roles vs scopes, BOLA, OWASP, password storage, secrets Explain your capstone's security model end to end, and how each test proves it
Technical: testing Unit vs integration, mocks vs real dependencies, Testcontainers, what coverage does and doesn't tell you Walk through one bug that a test caught
Live coding or take-home A small secured API with tests, or extending an existing codebase Do the "secured wallet API with tests in 2 hours" exercise twice; once without AI tools
System design (light) A small service with a database, a provider integration and failure handling Use your capstone's five architecture views as the template
Behavioural Ownership, collaboration, review, learning, mistakes Seven STAR stories (below)

Questions you should be able to answer cold

Revise with the Java fundamentals revision sheet and keep up the timed coding-interview practice track.

  1. What happens to a request in Spring Security before it reaches your controller?
  2. How does a resource server validate a JWT, and which claims must it check?
  3. Client credentials vs authorisation code with PKCE: who uses each, and why?
  4. Roles vs scopes vs ownership: give an example of each in a payment API.
  5. What is BOLA, and how do your tests prove you prevented it?
  6. How would you make a payment initialisation endpoint idempotent? And a webhook receiver?
  7. Timeouts, retries, circuit breakers: how do they interact, and what must never be retried?
  8. Offset vs cursor pagination: trade-offs.
  9. What does Testcontainers give you that an H2 database doesn't?
  10. What does 80% line coverage not tell you? How would you find weak tests?
  11. Merge vs rebase, and what makes a good pull request?
  12. How do you review AI-generated code before merging it?

Seven STAR stories

The five from Phase 1, plus:

  1. An integration that failed in an unexpected way (a timeout, a duplicate webhook, a provider contract surprise) and how you made the system robust to it.
  2. A review that changed your code, or a review you gave that prevented a defect, including AI-generated code you rejected.

Applications and the first 90 days

  • Re-map your shortlist to evidence (60%+ match rule from Phase 1). Phase 2 widens it: junior backend engineer, integration engineer, API developer, payments engineer, junior DevSecOps.
  • Lead with referrals: share your capstone write-ups on LinkedIn and in meetups, and ask for feedback rather than jobs.
  • Prepare for the first 90 days in a job, a common interview question: "learn the codebase and on-call runbooks, ship a small fix in week two, write tests where you touch code, ask good questions in reviews."
  • Phase 3 (Kafka, microservices, Kubernetes, cloud) continues in week 26; each module adds a line to your CV.
